# Collapse state is independent per folder, not cascaded into children

We considered making "collapse" a cascading action: collapsing a parent folder would set all descendant folders' state to collapsed too, and expanding the parent would reset them to expanded. We rejected this. Instead, each folder has its own independently remembered collapsed/expanded state, and a folder is only *rendered* hidden when itself or any ancestor is collapsed. This means re-expanding a parent restores each child to whatever state it individually had before — a folder you deliberately collapsed doesn't "pop back open" just because an ancestor was re-expanded. This is also the direct fix for BNTP's core bug: BNTP renders subfolders as flat siblings rather than a true nested tree, so parent/child collapse relationships don't work correctly there at all.
